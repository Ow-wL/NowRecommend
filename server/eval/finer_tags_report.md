# 조건 태그 세분화 평가 (finer-tags-v1, 2026-11-10)

새 조건 태그: 음식 야식·해장·든든함·가벼움, 음악 드라이브·출퇴근·새벽·감성. 함께 상큼함에 '새콤' 규칙을 더했어요.

## 요약

- **문장 해석**: "숙취 해장할 국물", "둘이서 든든하게 저녁", "새벽 감성 노래", "드라이브할 때", "출근길에" 같은 상황어가 조건 칩으로 잡혀요. 규칙이 다 읽은 문장은 서버가 해석 모델을 부르지 않아요. 예를 들어 "숙취 해장할 국물"은 예전에는 '숙취·해장할'이 남아 모델을 불렀어요(`shared/parse-cases.json` 25개 추가).
- **AI 엔진(운영 기본)**: 효과가 보이지 않아요. 바뀐·새 사례 14개에서 잘 맞음은 옛 태그 88~95%, 새 태그 90~93%로 실행마다 생기는 차이 안이에요. AI는 문장을 직접 읽으므로, 태그가 없어도 "해장"을 이미 이해하고 있었어요. 조건이 그대로인 42개도 기준선보다 나빠지지 않았어요(아래 회귀 검사).
- **카탈로그 엔진(AI 실패 시 대체, 즐겨찾기 범위)**: 효과가 있어요. 원하는 새 태그를 가진 추천이 34/58에서 58/58로 늘었어요. 바뀐·새 음식 사례의 잘 맞음은 78%→89%, 반대 추천은 6%→0%예요(FS6 "숙취 해장할 국물"의 마라탕, FN1의 떡국이 빠짐). MT2a "출근길"(차분한 취향)은 2/5→4/5예요. 전체로는 음식 77%→78%, 음악 83%→86%, 반대 추천 2%→0%, 3%→2%예요.
- **나빠진 곳**: 카탈로그 FN2 "다이어트 중이라 가볍게 점심"이 2/3→1/3이에요. 콩나물국밥 대신 연어 초밥과 딤섬이 나왔는데, 심사는 '밥이 들어감', '종류에 따라 다름'이라며 1점을 줬어요. MS3t·MN4는 5곡 중 1곡씩 내려갔어요.

## 측정 방법

- 바뀐 사례 6개(FS4·FS6·MS3·MS6·MT2a·MT2b)는 원래 조건을 그대로 두었어요. 기준선 실행과 사람 검수가 본 조건이기 때문이에요. 같은 문장을 새 태그 조건으로 묻는 사례는 FS4t처럼 이름 끝에 t를 붙여 따로 두었어요. 새 상황 사례는 FN1~4와 MN1~4예요(평가 세트 48→62개).
- `base-r1/r2`는 origin/main 코드가 옛 규칙의 조건으로 답한 실행이에요. `tags-r1/r2`는 이 브랜치 코드가 새 조건으로 답한 실행이에요. 바뀐·새 사례 14개는 양쪽 다 2회씩 돌렸고, `tags-r1`은 62개 전체를 돌렸어요. 모델은 gemini-3.5-flash-lite예요.
- 심사는 양쪽 모두 이 브랜치의 사례 정의(새 태그 wanted)로 받았어요(gemini-3.6-flash). 사람 검수가 아닌 AI 심사라서 흐름을 보는 용도예요.
- `cat-base`와 `cat-tags`는 카탈로그 엔진 실행이에요. 로컬 DB 두 개에 각각 옛 카탈로그와 새 카탈로그를 넣고 임베딩까지 새로 만들었어요. 운영 DB가 아니고, 각 DB는 그 코드 시점의 카탈로그예요(새 DB에는 비건 메뉴가 없음).

## 회귀 검사

`regressions()`로 조건이 같은 42개를 tags-r1과 비교했어요.

- guard-r1 기준(음식): 나빠진 항목 없음.
- ai-r1·ai-r2 기준(음악): 음악 '제외 위반(심사)'이 0%에서 13%로 나왔어요(MX2·MX3·MX5에서 4곡). 확인한 결과는 이래요.
  - 음악 제외 사례 6개를 두 번 더 돌렸어요(`mx-r3`, `mx-r4`). 각각 30곡 중 1곡이었어요.
  - 같은 날 main 코드로도 두 번 돌렸어요(`base-mx-r1/r2`). 0곡과 1곡이었어요.
  - 가장 자주 걸린 MX2 "보컬 없는 신나는 곡"만 양쪽에서 4번씩 돌렸어요(`mx2-main-*`, `mx2-tags-*`). main 2/20, 브랜치 1/20이었고, 같은 곡 Clocks가 양쪽 모두에서 나왔어요.
  - 그래서 태그 변경 때문이 아니라 원래 있던 약점의 흔들림으로 봐요. 음악에는 제외 검사가 아직 서버에 없어요.
