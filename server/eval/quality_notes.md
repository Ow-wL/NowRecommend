# 비슷한 곡 요청과 히트곡 쏠림 (2026-11-24)

사용자 후기: "한로로의 입춘이랑 비슷한 노래"에 입춘 자체와 장르가 다른 히트곡(윤하, 자우림, 아이유)이 나왔어요. 평가 세트에 "비슷한 곡" 13사례(MR1~13, `seed`에 기준곡)를 더하고, 심사에 `famous`(널리 아는 히트곡)와 "비슷한 곡이면 소리가 가까운지로 매긴다"를 더했어요. 같은 심사 모델(3.6-flash).

| 실행 | 코드 | 모델 | 비슷한 곡: 잘 맞음 | 히트곡 | 기준곡 반환 | 응답 p50 | 기존 30사례: 잘 맞음 | 히트곡 |
|---|---|---|---|---|---|---|---|---|
| sim-base-r1 | 운영(00034) | 3.5-flash-lite | 29% | 77% | 13건 중 5건 | 3.5s | 79% | 89% |
| sim-new-r1/r2 | 기준곡 + 히트곡 문구 + 정렬 | 3.5-flash-lite | 37% / 35% | 54% / 58% | 0 / 0 | 3.8s / 4.0s | 86% | 91% |
| sim-flash-r1 | 위와 같음 | 3.6-flash | 57% | 68% | 0 | 8.7s (7.8~10.4s) | - | - |

바꾼 것: 모델이 picks 앞에 `reference`(기준곡·아티스트·핵심 소리)를 먼저 쓰고, 서버가 그 제목의 곡을 빼고 기준 아티스트는 1곡까지만 둬요. "확실한 곡 먼저" 문구를 "히트곡만으로 채우지 않고 이웃 아티스트·수록곡도 1~2곡"으로 바꿨어요. 아티스트 한 곡 규칙을 스토어 정렬 뒤로 옮겼고, 이미 본 곡으로 빠진 자리를 예비곡이 채워요.

**배포 뒤 바로잡음(같은 날):** 스토어 확인을 고친 뒤(괄호 뺀 검색어) 각 실행의 비슷한 곡 픽을 스토어에 다시 물었어요. 히트곡 문구가 없는 곡을 늘렸어요.

| 실행 | 히트곡 문구 | 비슷한 곡: 잘 맞음 | 히트곡 | 스토어에 없음 | 기존 30사례: 스토어에 없음 |
|---|---|---|---|---|---|
| sim-base-r1 | 없음(운영 전) | 29% | 77% | 16/58 (28%) | 20/104 (19%) |
| sim-new-r1/r2 | 있음 | 37% / 35% | 54% / 58% | 31/62 (50%) / 29/64 (45%) | 17/106 (16%) |
| sim-nopop-r1 | 없음 + 기준곡 처리 | 37% | 74% | 17/59 (29%) | - |
| sim-flash-r1 | 있음, 3.6-flash | 57% | 68% | 15/60 (25%) | - |

스토어에 없다고 곧 없는 곡은 아니지만(썸 탈거야 - 볼빨간사춘기는 실존), 늘어난 몫은 지어낸 곡과 잘못 붙인 아티스트("지구멸망"을 세 아티스트에게, "Beach Fossils - What a Pleasure")였어요. 심사 모델은 이걸 2~3%로만 잡아 믿을 수 없어요. 결정: 히트곡 문구를 원래대로 되돌리고 기준곡 처리만 남겨요(sim-nopop). 기존 요청의 히트곡 비율은 문구로 거의 바뀌지 않았어요(89% → 91%). 덜 알려진 곡을 늘리려면 lite로는 지어낸 곡이 늘어서, 더 큰 모델이나 외부 유사도 데이터가 필요해요.

읽는 법: 기준곡 반환과 히트곡 비율은 확실히 나아졌어요. 비슷한 곡의 잘 맞음은 여전히 낮은데, 남은 감점은 대부분 lite의 곡 지식(아티스트를 잘못 붙임, 같은 씬을 모름)이에요. 3.6-flash는 57%로 높지만 응답이 두 배이고 지금 AI 대기 한도(10초)에 걸릴 수 있어, 비슷한 곡 요청에만 쓸지는 따로 정해요. 기존 30사례의 히트곡 비율은 문구만으로는 거의 안 바뀌었어요.

# 음악 추천 품질 개선 (2026-11-23)

같은 30개 음악 사례, 같은 심사 모델(gemini-3.6-flash). 심사는 사람보다 음악을 15~20%p 후하게 보므로 절대값보다 실행 사이의 차이로 읽어요(eval/review/findings.md).

| 실행 | 프롬프트 | 모델 | 잘 맞음 | 응답 p50 | 서로 다른 곡 | 스토어 못 찾음 |
|---|---|---|---|---|---|---|
| q-base-r1/r2 | 운영(이전) | 3.5-flash-lite | 81% / 80% | 2.8s / 2.9s | 105 / 103 | 3 / 5 |
| q-new-r1/r2 | 소리 먼저·제목 낚시 금지·원곡 아티스트·예비 4곡 | 3.5-flash-lite | 91% / 84% | 4.1s / 4.3s | 99 / 91 | 2 / 0 |
| q-new2-r1/r2 | 위 + "히트곡 습관 금지" | 3.5-flash-lite | 80% / 83% | 3.8s / 4.0s | 104 / 94 | - |
| q-flash-r1 | q-new와 같음 | 3.6-flash | 89% | 7.3s | 106 | 5 |

결정: q-new 프롬프트, 모델은 그대로(lite). "히트곡 습관 금지"는 맞음 비율과 제외 지킴이 나빠져 뺐어요. 3.6-flash는 맞음이 비슷하고 응답이 두 배 가까이 느려요.
남은 약점: 같은 히트곡(Dynamite, Blinding Lights 등)이 여러 요청에 반복돼요. 스토어 조회는 분당 한도 때문에 평가에서 절반쯤 '조회 실패'라 실존 비율은 하한선이에요.
